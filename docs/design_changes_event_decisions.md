# 设计变更：事件内部决策系统

> **版本**: v0.2（已评审定稿）
> **关联文档**: game_design.md §3.5, §11
> **变更动机**: 解决玩法深度薄与进程感弱的问题

---

## 一、问题诊断

### 当前设计的根本缺陷

现有事件系统是**单向的**：玩家移动到格子 → 翻牌 → 结果发生在玩家身上 → 玩家承受。

整个过程中玩家没有主动决策，只是结果的接收方。这导致：

- **玩法深度薄**：真正意义上"我权衡后做了一个选择"的时刻极少，核心决策只剩路径规划（去哪）
- **进程感弱**：第 1 天和第 10 天的决策结构完全一样，资源状态的变化没有改变玩家的决策空间

### 为什么路径规划不够

路径规划（如何用有限步数覆盖所有日程目标）是有价值的决策，但它发生在**翻牌之前**。翻牌这个动作本身——游戏中最高频的操作——没有决策内容，是纯粹的随机承受。

## 二、核心设计变更：事件内部决策

### 变更原则

翻开卡牌后，玩家面对一个情境，需要选择**如何应对**，而不是直接承受固定结果。

**关键设计约束**：决策选项的最优解必须依赖玩家当前的资源状态。不能出现"A 选项永远更好"的情况——如果有明显优势选项，决策就失去意义。

```
理想决策结构示例（遭遇怪物）：

  A. 逃跑    → 消耗步数，安全撤离
  B. 对抗    → 消耗理智（低于默认扣除），成功则获得奖励
  C. 用道具  → 消耗护身符，最稳定（仅在有护身符时显示）

资源状态决定最优解：
  - 步数充裕  → A 可接受
  - 理智充裕  → B 更划算
  - 有护身符  → C 最稳
  - 三者皆匮乏 → 硬撑（接受最差结果，即 B 的代价）
```

### 条件选项规则

**"用道具"系列选项只在玩家背包中有对应道具时显示。** 不做条件提示或灰色显示——不满足条件的选项直接不出现，保持界面整洁。

## 三、各事件类型决策设计（定稿）

> 具体数值待平衡，以下为结构定稿。

### 3.1 Monster（怪物）

> 适用于：翻开的活怪物格（`card.type == "monster"`）

核心张力：步数代价 vs 理智代价 vs 道具消耗

| 选项 | 显示条件 | 消耗 | 结果 |
|------|---------|------|------|
| 逃跑 | 始终 | 步数 -2 | 安全撤离，无资源损失 |
| 对抗 | 始终 | 理智 -1（减半） | 成功则金钱 +10；失败仍扣理智 -2（净差 -1） |
| 用护身符 | 有护身符时 | 消耗护身符 | 稳定解决，无任何损失 |

### 3.2 Trap（陷阱）

> 适用于：翻开的陷阱格（`card.type == "trap"`）

核心张力：步数绕路 vs 接受伤害 vs 道具消耗

| 选项 | 显示条件 | 消耗 | 结果 |
|------|---------|------|------|
| 硬闯 | 始终 | 按陷阱子类型扣减（标准） | 直接通过 |
| 绕路 | 始终 | 步数 -2 | 安全通过，无资源损失 |
| 用护身符 | 有护身符时 | 消耗护身符 | 稳定解决，无任何损失 |

### 3.3 Safe（安全）

> 适用于：普通安全格（`card.type == "safe"`）

核心张力：保守恢复 vs 冒险探索 vs 胶卷投资

| 选项 | 显示条件 | 消耗 | 结果 |
|------|---------|------|------|
| 休息 | 始终 | 无 | 理智 +1 **或** 健康 +1（玩家二选一） |
| 搜查 | 始终 | 步数 -1 | 随机：发现道具 / 发现金钱 / 什么都没有 |
| 拍照留念 | 有胶卷时 | 胶卷 -1 | 金钱 +5 |

### 3.4 Reward（奖励）

> 适用于：奖励格（`card.type == "reward"`）

核心张力：稳拿 vs 冒险加倍

| 选项 | 显示条件 | 消耗 | 结果 |
|------|---------|------|------|
| 直接拿 | 始终 | 无 | 获得默认奖励（金钱 +15 或长期胶卷 +1） |
| 深挖 | 始终 | 步数 -1 | 50% 双倍奖励 / 50% 触发隐藏陷阱效果 |

### 3.5 Plot（叙事推进格）

> 适用于：叙事推进格（`card.type == "plot"`）

核心张力：被动旁观 vs 主动参与代价

| 选项 | 显示条件 | 消耗 | 结果 |
|------|---------|------|------|
| 旁观 | 始终 | 无 | 获得基础叙事文本，理智 -1 |
| 记录 | 始终 | 灵感 -1 | 获得更完整的叙事信息，推进白夜故事线 |
| 介入 | 始终 | 健康 -1 | 直接推进剧情，可能解锁额外对话或碎片 |

### 3.6 Photo（遗址调查）【新增】

> 适用于：已被拍照消灭的格子（`card.type == "photo"`）  
> **仅触发一次**：用 `card.photo_investigated` 标记，触发后不再弹决策面板  
> **图片**：沿用原怪物/陷阱的地点图片（`card.pre_photo_type` + `card.location` 查图）

核心张力：快速通过 vs 深入调查的资源代价

| 选项 | 显示条件 | 消耗 | 结果 |
|------|---------|------|------|
| 离开 | 始终 | 无 | 直接通过，无效果 |
| 继续调查 | 始终 | 灵感 -1 | 接入 `clue_events` 数据池，有概率获得线索/情报 |
| 拍照留档 | 有胶卷时 | 胶卷 -1 | 金钱 +8（将调查现场变现） |

## 四、跨类型转化（更新版）

### 放弃直接转化路径

原草案中 monster→clue（观察记录）和 trap→clue（侦测）的**即时转化不再实现**，原因：

相机拍摄 = 立即消灭，不存在"拍了但还在"的中间状态，设计逻辑矛盾。

### 改为遗址调查路径

被相机消灭的危险格留下 **Photo 遗址**，玩家**之后再踩**时触发一次性调查事件（3.6 节）。

```
有怪物/陷阱的格子
  ├─ 玩家用相机 → 立即消灭（原有流程不变）→ 格子变 Photo 遗址
  │                                           └─ 再次踩到（一次性）→ 遗址调查决策
  └─ 玩家直接翻牌 → 怪物/陷阱决策面板（3.1 / 3.2）
```

相机的策略价值变了：**拍照不只是安全消灭，而是在该位置留下一个可一次性调查的现场**——值不值得之后回来调查，是新的决策维度。

## 五、与相机系统的关系

### 相机系统行为不变

- **拍摄危险格（未翻开）**：消耗胶卷，翻开后立即消灭，变为 Photo 遗址格
- **拍摄安全格**：消耗胶卷，雷达功能（提示最近危险格位置）
- **拍摄已翻开怪物**：消耗胶卷，直接驱除，变为 Photo 遗址格

### 两套系统的互动关系

```
面对危险格时，玩家面临两个时机的决策：

  时机一（翻牌前）：用不用相机？
    ├─ 用相机：安全消灭，留下遗址（之后可一次性调查）
    └─ 不用：翻牌，进入战斗/陷阱决策面板

  时机二（翻牌后）：根据当前资源状态选择应对方式
```

## 六、UI 实现方式

### 决策按钮替换"知道了"

在现有笔记本弹窗布局中，决策按钮**替换底部的"知道了"按钮**：

- 有决策时：底部显示 2-3 个选项按钮（横排或纵排，按选项数自适应）
- 无决策时（shop/NPC 等阻断型）：保持原有"知道了"单按钮

按钮样式沿用现有 `show_choice` 的深色胶囊风格，在笔记本内嵌而非浮层覆盖。

### Photo 格图片复用

Card 需新增 `pre_photo_type: String` 字段，在相机消灭流程将 `card.type` 改为 `"photo"` 之前记录原类型。

查图时用 `CardImageMap.get_event_texture(card.location, card.pre_photo_type)` 而非 `"photo"` 类型。

## 七、技术实现计划

### 数据层

- `event_pool.json` 每个事件条目加 `"choices"` 数组字段
- `choices` 元素结构：`{ "label", "cost", "result", "condition" }`
- `card.gd` 新增 `pre_photo_type: String` 和 `photo_investigated: bool` 字段

### 逻辑层

- `EventHandler.EventResult` 加 `choices: Array` 字段
- `EventHandler._build_result_from_event()` 填充 choices
- `card_interaction.gd` 翻牌后：检测 `result.choices` 是否非空，若有则传入弹窗

### UI 层

- `EventPopupScene`：`show_event_data()` 加 `choices` 参数
- 有 choices 时：底部渲染多按钮行，替换单"知道了"按钮
- 选择后：`popup_closed` 携带选择结果，`card_interaction` 根据选择应用对应效果
