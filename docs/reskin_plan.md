# 换皮计划：暗面都市 → 梦魔心理医生

> 注：「换皮」是方便描述的简称。实际上两款游戏的核心玩法（卡牌战斗）存在架构级差异，
> 本文档准确描述哪些可以复用、哪些需要改造、哪些需要重建。

---

## 一、核心架构差异概述

| 维度 | 暗面都市（现有） | 梦魔心理医生（目标） |
|------|-----------------|---------------------|
| 地图含义 | 现实城市街区 | 病人的心灵迷宫 |
| 主要玩法 | 翻格触发多选事件 | 翻格触发事件 + **牌库构建战斗** |
| 暗面层 | 独立系统（3层纵深，幽灵AI，能量条） | **与表层相同框架**，4×4缩小版，事件内容不同 |
| 地图内NPC | 城市路人（房东/猫/护士），随机出现 | **记忆回声**（病人生命中的人），按叙事触发 |
| 进度结构 | 7~14天线性推进，单角色剧情 | 4个独立迷宫（3外围+1核心），章节结构 |
| 结局判定 | 白夜信任度 + flag组合 | 信息完整度 × 最终选择 |

结论：**棋盘框架/事件框架/对话框架可以复用；卡牌战斗系统需要重建；暗面层需要重构为表层的配置变体。**

---

## 二、可直接复用（改配置，不动代码）

这些系统架构上无需变动，替换数据文件即可：

### 2.1 数据文件替换清单

| 文件 | 替换内容 |
|------|---------|
| `data/game_config.json` | 资源名称/图标/初始值/上限、天数配置 |
| `data/story_config.json` | 章节/线索/flag/结局条件/结局展示文本（完全重写内容） |
| `data/card_config.json` | 地点名称/图标、事件权重、暗面格子名称 |
| `data/locations.json` | 病人迷宫的地点定义（从「城市地点」改为「记忆场景」） |
| `data/npc_dialogues.json` | NPC对话内容（从城市路人改为记忆回声的台词） |
| `data/morning_events.json` / `evening_events.json` | 晨间/夜间事件文本（从苏柚视角改为医生+病人视角） |
| `data/milestone_events.json` | 里程碑事件（章节推进节点） |
| `data/shop.json` | 商店内容（新游戏为「诊断费外购道具」机制） |
| 所有音效/BGM文件路径 | `data/audio_manager.gd` 中的映射表 |
| 所有图片资源 | 立绘/背景/chibi/卡面 |

### 2.2 可直接复用的系统模块

- **StoryManager**：flag增删改查、条件求值系统、线索收集——逻辑完全通用
- **DialogueSystem + SideBubble**：对话框+气泡，只需替换内容
- **EndingSystem**：按优先级遍历条件的框架通用，替换endings数组内容
- **DateTransition**：日期切换动效（或改为「就诊结束」切换效果，视具体设计）
- **AudioManager**：替换音效映射表即可
- **SaveManager**：替换存档字段名即可
- **WeatherSystem**：如需保留天气概念（心理状态天气化），可复用

## 三、需要改造（改代码逻辑，部分复用）

### 3.1 暗面层 → 统一迷宫生成器（重要架构决策）

**现状**：暗面都市的暗面层是一套独立系统（`dark_world.gd`），有专属的：地图生成逻辑、幽灵AI、能量条、三层纵深、层间传送点。

**问题**：新游戏的暗面层本质上只是「同一套棋盘框架的缩小变体」：
- 尺寸：4×4（而非5×5）
- 事件内容：更压抑、更核心情感
- 锚点机制：暗面层特有，但是棋盘系统的扩展，不是独立系统

**建议方案**：将 `Board`（棋盘）设计为可配置的迷宫生成器，通过配置区分表层和暗面层：

```
MazeConfig {
    size: 5×5 / 4×4
    event_pool: "surface" / "dark"
    has_anchor: false / true
    has_rift: true / false
    atmosphere: "normal" / "oppressive"
}
```

暗面都市的 `dark_world.gd` 中可复用的部分：
- **幽灵AI移动逻辑**（追逐+游荡）→ 在新游戏中幽灵可改为「压抑情绪体」
- **进出场动画触发逻辑** → 复用

可以删除的部分：
- 三层纵深系统（新游戏单层）
- 能量条系统（新游戏用步数，统一资源框架）
- 层间传送点（单层不需要）

### 3.2 NPC系统 → 记忆回声系统（叙事含义重新定义）

**现状**：暗面都市的NPC是「城市地图上的路人」，和地图外的角色（苏柚/白夜）是两套概念。NPC随机出现在格子上，提供资源交换/教程触发。

**新游戏的问题**：地图现在是「病人的心灵迷宫」，在这里随机出现一个提供资源交换的「房东」毫无意义。地图内出现的人物必须来自病人的记忆，叙事上才成立。

**建议方案：记忆回声（Memory Echo）**

心灵迷宫里出现的人物是病人记忆里的真实存在，表现为「残影/回声」状态。技术上复用NPCManager的框架，但语义完全不同：

| 维度 | 暗面都市NPC | 梦魔新游戏记忆回声 |
|------|------------|-----------------|
| 出现位置 | 城市地图（城市场景） | 心灵迷宫（心理场景） |
| 出现逻辑 | 随机/按地点概率 | 按叙事条件触发（剧情节点/已收集某线索后出现） |
| 身份 | 无名路人/教程NPC | 病人生命中的具体人物（家人/朋友/施害者/证人） |
| 互动性质 | 资源交换/教学 | 对话获取线索 / 情绪触发 / 部分可对抗 |
| 是否有名有姓 | 通用类型（「房东」「猫」） | 病人记忆中的具名人物 |
| 视觉风格 | 正常chibi | 残影/半透明/略微扭曲（表示这是记忆而非真人） |

**每个病人迷宫的记忆回声示例**（待详细设计时填入）：
- **林柠（便利店员工）的迷宫**：深夜店长、某个常客、她妹妹？
- **陈桐（教师）的迷宫**：某个学生、教务主任、她丈夫？
- **苏鸥（摄影师）的迷宫**：那个「消失的男性」、相机店店主？
- **季萱白（修女）的迷宫 Phase 1**：教会其他修女、神父、被带走的孩子们

**玩家与记忆回声的互动模式**（建议）：
1. **对话获取线索**：交谈后触发对话事件，可能给出线索/san消耗/步数消耗
2. **沉默通过**：不互动直接经过，回声消散（错过线索机会）
3. **情绪对抗**（仅部分敌对回声）：触发小规模卡牌战斗，获胜可获取线索

**NPCManager代码层面**：框架复用，替换：
- npc类型定义（`_npc_types`字典）
- 出现条件（从概率改为叙事flag判断）
- 互动结果（从资源交换改为线索/san收支）

> **注**：同一套 NPCManager 框架同时服务于两种 NPC——迷宫内的「记忆回声」（互动深度：完整对话+线索触发）和城市地图的「氛围路人」（互动深度：气泡台词即关闭）。两者共享放置逻辑和 flag 判断，互动结果分支不同。

### 3.3 进度结构 → 章节化迷宫入口

**现状**：暗面都市是线性天数推进，每天发新棋盘。

**新游戏**：4个独立迷宫（林柠→陈桐→苏鸥→季萱白），每个迷宫是一次独立「就诊」。

改造点：
- 去掉「天数」推进逻辑，改为「就诊次数」或「迷宫章节」
- 棋盘生成从「每天随机」改为「按章节配置生成」（每个病人有专属的地点池和事件池）
- `game_flow.gd` 的 `advance_day()` 逻辑改为 `complete_session(patient_id)`

### 3.4 结局系统 → 信息完整度×最终选择

**现状**：EndingSystem遍历结局条件，条件基于白夜信任度+flag。

**改造**：同样的遍历框架，替换条件为：
- `info_complete`：是否获得了认知污染根源完整情报（bool）
- `final_choice`：结局节点的玩家选择（"unseal" / "keep_sealed" / "third_path"）
- 修女情感线变体：`has_affection_for_nun`（bool）

结局定义（4+1条）：
```json
{
  "endings": [
    { "id": "ending_a", "条件": "info_complete=true AND final_choice=unseal" },
    { "id": "ending_b1", "条件": "info_complete=false AND final_choice=keep_sealed" },
    { "id": "ending_b2", "条件": "has_affection_for_nun=true AND final_choice=keep_sealed" },
    { "id": "ending_c", "条件": "info_complete=true AND final_choice=third_path" },
    { "id": "ending_default", "条件": null }
  ]
}
```

## 三·五、关卡外界面（全新开发）

暗面都市没有关卡外城市地图，这部分是梦魔心理医生完全新增的系统。

### 城市地图

| 要素 | 说明 |
|------|------|
| **布局** | 大富翁路径式：树状/网状路径，地点卡位于路径节点，道路格用于移动 |
| **移动** | 玩家以主角 chibi 在路径上行走（路径移动，不是自由移动） |
| **地点卡** | 医疗机构/商店/情报点/诊所入口等，不填满整张地图 |
| **氛围NPC** | 道路格上随机路人 chibi，可点击触发1~2句台词，不消耗行动力，不影响数值 |
| **视觉风格** | 城市俯视，卡牌拼成路径，Muse Dash 活泼风 |

**氛围NPC → 复用现有 NPC 系统框架（裁剪版）**

城市路人是迷宫 NPC 系统的「功能裁剪版」，可以复用以下部分：

| 复用模块 | 用途 | 改动 |
|---------|------|------|
| `SideBubble` / `DialogueSystem` | 点击触发台词气泡 | **无需改动**，直接复用 |
| `NPCManager` 随机放置逻辑 | 把 NPC 分配到路径格 | 替换放置目标：迷宫格子 → 城市道路格 |
| `StoryManager` flag 判断 | 章节推进后 NPC 出现/消失 | **无需改动**，flag 条件替换为章节条件 |

去掉的部分：
- ~~资源交换/子系统入口~~（路人台词结束后直接关闭，不进入任何子系统）

**新增工作量（仅内容，不是系统）**：
- chibi 路人素材若干套（性别+姿态变化）
- 台词池（通用台词20~30条 + 各章节专属台词若干条）

### 诊所界面

| 要素 | 说明 |
|------|------|
| **形式** | 第一视角固定场景，场景内有可点击物件 |
| **物件** | 档案柜（信息板入口）、书架（碎片详细文本）、门口（返回城市地图） |
| **叙事** | 特定节点触发立绘+独白（与城市地图的叙事触发统一管理） |

### 支线病人（问诊小游戏）

与目标病人的棋盘迷宫玩法完全不同，是新建的独立小游戏系统：

```
问询阶段（选项对话）→ 状态判断阶段（判断题）→ 诊断方案 → 结算
```

| 要素 | 说明 |
|------|------|
| **答对/答错** | 诊断费固定，答错仅触发叙事后果（台词变化），不惩罚数值 |
| **梦魔作弊** | 可跳过判断直接获得正确答案，代价是主动触发战斗（san消耗） |
| **战斗** | 复用主牌组/战斗系统，不引入新机制 |
| **叙事功能** | 补充城市世界观，病人角色为一次性路人 |

**开发工作量**：
- 问诊对话UI（问答流程，非迷宫）
- 判断题逻辑（题目+正确/错误分支）
- 叙事后果触发器（台词变体管理）
- 梦魔作弊选项 → 战斗触发接口
- 支线病人数据表（4~6名，每人：背景/问题/判断题/台词）

## 四、需要重建（从零开发）

### 4.1 卡牌战斗系统

这是新游戏区别于暗面都市的**核心**，无法从现有代码改造而来，需要完整新建。

涉及模块：
- `CardBattle`：战斗状态机（玩家回合/结算/结果）
- `Hand`：手牌管理（摸牌/打出/弃牌）
- `Deck`：牌库/弃牌堆管理
- `BattleCard`：单张战斗卡数据（费用/效果/类型）
- `BattleUI`：战斗界面（手牌显示/出牌动画/结算展示）
- `EnemyAction`：敌方行动预告（Boss战专用）

**开发前置条件**：卡牌战斗系统详细规则必须先在设计文档中完整定义（见待定义清单）。

### 4.2 迷宫配置系统

将现有 `Board` 和 `DarkWorld` 整合为一套可配置的迷宫生成器（见3.1节）。

每个病人需要一份独立的迷宫配置文件：
```
data/mazes/
  lin_ning.json    # 林柠的心灵迷宫配置
  chen_tong.json   # 陈桐的心灵迷宫配置
  su_ou.json       # 苏鸥的心灵迷宫配置
  ji_xuan_bai_p1.json  # 季萱白 Phase 1
  ji_xuan_bai_p2.json  # 季萱白 Phase 2
```

每份配置包含：地点池、事件权重、记忆回声出现条件、是否含暗面层、锚点初始区域。

## 五、开发阶段建议

### 阶段0：设计文档补全（先决条件）

在写任何代码前，必须先完成以下设计文档：
1. 完整资源系统表（san/health保留，其余如何处理）
2. 卡牌战斗详细规则（行动点/回合/计算公式）
3. 通用记忆卡完整列表（8~10种，有名称和数值）
4. 至少一个病人迷宫的记忆回声清单（验证系统设计可行性）

### 阶段1：数据层换皮

- 替换所有 `.json` 配置文件内容
- 替换图片/音效资源
- 不动代码逻辑
- **验收**：能跑起来，资源栏显示新名称，对话内容是新文本

### 阶段2：系统改造

- 暗面层整合为统一迷宫生成器
- NPC系统改为叙事触发的记忆回声
- 进度结构改为章节化
- 结局条件替换
- **验收**：完整走通林柠迷宫（含表层+暗面层），结局系统正确判定

### 阶段3：新系统重建

- 卡牌战斗系统
- 迷宫配置系统（按病人分文件）
- **验收**：卡牌战斗完整流程可玩，不同病人迷宫有差异化体验

### 阶段4：内容填充

- 补全4个病人的完整内容（对话/事件/记忆回声台词）
- 修女Phase 2 Boss战
- 四条结局线剧情文本
- **验收**：全流程通关，四条结局均可触达

## 六、风险提示

1. **卡牌战斗系统是最大不确定项**：开发量难以提前估计，设计规则若在开发中变更会导致大量返工。建议阶段0完成后先做一个可玩的战斗原型验证手感，再进入正式开发。

2. **记忆回声需要大量叙事内容**：每个病人迷宫需要设计3~5个有名有姓的回声角色+对话内容，这是内容工作量，不是技术工作量，需要提前规划。

3. **暗面层整合可能触动现有测试**：暗面都市目前暗面层是独立运行的，整合成统一框架时需要注意保证原版暗面都市也能正常运行（如果需要保留的话）。
